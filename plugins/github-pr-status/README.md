# GitHub PR Status

Owns GitHub pull request data and actions for bb environments. Bundled and enabled by default.

- `host.ts` batches GraphQL reads through `gh api graphql` and runs `gh pr ready|merge` in the environment's workspace on its machine.
- `server.ts` resolves environments, assembles the status core's PR UI renders, serves the keyed `pullRequests` read and the `markReady`, `markDraft` and `merge` mutations, and registers `bb pull-request`.
- `store.ts` shares snapshots, in-flight reads and pending-check timers by PR URL, and publishes only changed rows.
- `persistence.ts` uses the plugin's own database through `bb.storage.database()` / `migrate()`. It stores each environment's current link (a PR URL, or known absence) and the snapshots those links reference. Snapshots no link references are deleted. Identical PR content and links do not write rows; after a restart the app is served saved content immediately and refreshed in the background, while CLI and plugin reads wait for overdue data.
- `app.tsx` registers the sidebar row badge through `app.slots.experimental_threadRowItem`: the current-branch PR's state icon and checks dot, read only while the row is live (on screen after a scroll pause). `display.ts` holds the state, next-step and check labels the badge and core's PR UI share.
- `contract.ts` is the public contract. Core's composer banner, Info row and sidebar shim read through it with `pluginId: "bb--github-pr-status"`, the way any other plugin would. Its `pullRequestStaleAfterMs` rule (30 s open, 1 h merged or closed) decides both the app's window-focus refresh and whether a watch re-reads its row.

Plugin host calls never wake a suspended machine: reads return `unavailable`, and actions fail with a message naming the machine.

Branch discovery follows `gh pr view`: the base repository is the remote `gh` resolved (`gh repo set-default`), else `upstream`, `github`, `origin`, then any other remote, and `GH_REPO` overrides it. A branch pushed to another owner's remote matches only that owner's fork PRs; otherwise only same-repository PRs match, and the default branch ignores merged and closed PRs. Actions still target the current branch and bypass the discovery cache.

Watched open PRs with pending checks, unknown mergeability, a merge queue entry or auto-merge refresh about every 30 seconds on one aligned tick: a PR due within 15 s joins the current tick, and the tick's loads reach each machine as one `views` call whose reads all start together. Changes from one tick publish as one invalidation. Quiet and settled PRs do not poll; foreground mount/focus and environment events still refresh them. A new quiet/absent reconciliation timer was excluded because main performs zero background reads in those states. Ref events compare the local upstream OID without fetching. Turns without a PR rediscover; known PRs recheck only after a turn that ran `gh`.

Reads on each workspace host are grouped by GitHub hostname and credential (including gh profile account changes) into documents of at most 100 URL reads or 25 branch reads (branch lookups list up to 100 PRs each) with a 10 ms collection window. Loads that start within 50 ms of each other (250 ms at most) reach each machine as one `views` call. Missing credentials or a sleeping host return unavailable. Rate limits pause the affected credential for at least one minute. A GitHub Enterprise server without merge queues is read without `isInMergeQueue` from then on. No credentials or ETags are persisted; measured ETag revalidation still needed two checks requests, versus one combined GraphQL request.
